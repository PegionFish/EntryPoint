# WebUI 使用指引

> 适用于 EntryPoint v0.x | WebUI 为唯一 UI（桌面端已于 2026-08-13 退役）

本文档逐页介绍 EntryPoint WebUI 的功能与典型操作。WebUI 由 ep-daemon 托管，
浏览器访问 `http://127.0.0.1:9800`（以 `config/app.toml [server]` 配置为准）
即可使用，无需安装客户端。

---

## 1. 导航结构

| 路由 | 页面 | 定位 |
|---|---|---|
| `/` | 仪表盘 | 设备、模块、依赖环境的全局状态总览 |
| `/modules` | 模块与模型 | 模块生命周期、模型获取/切换、整合包管理（统一页） |
| `/pipeline` | 管线编辑器 | React Flow 画布编排 DAG 管线并在线执行 |
| `/tasks` | 任务中心 | 任务状态跟踪、取消、产物下载 |
| `/settings` | 设置 | 全局配置（保存即落盘 `config/app.toml`） |

顶栏提供语言切换（简体中文 / English）与主题切换；界面文案走 i18n，
跟随「设置 → 通用」的语言配置。

---

## 2. 快速上手：一条典型流水线

```
① 仪表盘确认依赖环境就绪（Python/uv/ffmpeg）
② 模块页：启动需要的模块（首次自动准备 venv 依赖）
③ 模块页：下载/上传/导入该模块的模型，必要时切换激活变体
④ 管线页：选一条自带管线（如 video_to_srt），运行并选择输入文件
⑤ 任务中心：跟踪节点进度，完成后下载产物（如 .srt 字幕）
```

下文按页展开。

## 3. 仪表盘（`/`）

三个区块：

- **设备**：枚举到的计算设备（GPU/CPU）与状态指标，是模块设备分配的依据。
- **模块**：全部已安装模块的运行状态一览（运行中/准备中/错误等），
  可快速定位需要启动或排障的模块。
- **依赖环境**：运行前置依赖的检测卡片——FFmpeg（版本与路径）、
  各模块 venv 内的 PyTorch CUDA 可用性；缺失项会给出安装指引文案。
  新装机器先看这里，缺失项不解决，相应管线节点会失败。

## 4. 模块与模型（`/modules`，统一页）

模块详情独立页已裁撤，本页集中承载模块、模型与整合包三类操作，
详情一律以**抽屉**形式展开。

### 4.1 模块卡片与抽屉

- 每个模块卡片显示名称、类别、运行状态徽章、激活模型变体与设备信息；
  提供启动 / 停止（带确认）/ 重启操作。
- **模块详情抽屉**：模块元信息、声明的能力（capabilities）列表与参数
  schema、激活变体切换器。
- **直跑抽屉**：不走管线、对单个能力做 ad hoc 调用——选能力、选输入文件、
  按参数 schema 自动生成的表单调参后提交，适合快速验证模块效果。
- **日志抽屉**：实时查看 daemon 捕获的该模块输出日志（搜索/过滤/导出）。
- 变体切换：单槽位语义——切换激活变体后按提示**重启模块**生效；
  目标变体本地缺失时提示一键下载。

### 4.2 模型获取

模型按「模块 → 变体」分组展示，支持 tag chips 筛选。每个模型卡片/行提供：

- **在线下载**：HuggingFace / ModelScope / URL 三类源 + 模块声明的
  `[[models.mirrors]]` 镜像源，下载时可选源；WebSocket 实时进度，可取消。
  首次下载会自动准备模块 venv（含大型依赖时约 15–20 分钟，属预期行为）。
- **浏览器上传**：整个文件夹多文件、zip、tar.gz 三种形态，服务端流式
  落盘并解包。
- **本地导入**：从服务器/本机已有目录导入。
- 其他：检查更新、删除（卡内操作）。

### 4.3 整合包（pack）

- **整合包抽屉**：已安装整合包列表与卸载（可选保留模型权重）。
- **导入**：本地路径 / URL / 浏览器上传三种入口；导入自动完成校验、
  落位（模块 + 模型 + 管线）与适配报告。
- **导出**：把现成模块构建成整合包下载（模块导出构建）。

格式与安全模型详见 [PACK_AUTHORING.md](PACK_AUTHORING.md)。

## 5. 管线编辑器（`/pipeline`）

基于 React Flow 的 DAG 画布：

- **节点库**（宽屏常驻左栏，窄屏为抽屉）：内置节点（file_input /
  file_output / ffmpeg / llm）+ 已安装模块声明的全部能力，数据驱动自动
  生成；拖拽或点击加入画布。
- **连线**：按端口类型校验（音频/视频/图片/文本/JSON/文件），类型不兼容
  的连线会被拒绝。
- **节点参数面板**：模块节点的参数表单由 module.toml 的 params schema
  自动渲染；还可设置节点超时、重试、变体 pin 与设备软约束。
- **管线管理**：加载自带/已保存管线（`config/pipelines/*.toml`，如
  `video_to_srt.toml`、`audio_extract.toml`）、保存（服务端持久化）、
  TOML 导入/导出（便于分发与版本管理）。
- **VRAM 账本**：按画布上的模块节点估算每设备显存占用，超预算会标红提示。
- **运行**：选输入文件后提交执行；画布上实时回显各节点状态
  （排队/运行中/完成/失败），完整跟踪见任务中心。

管线格式与执行语义详见 [PIPELINE_SPEC.md](PIPELINE_SPEC.md)。

## 6. 任务中心（`/tasks`）

- 任务列表：状态徽章（排队/运行中/完成/失败/已取消）、提交时间、
  所属管线，支持按状态筛选。
- 任务卡片展开后可见**节点级**进度与各节点耗时/错误信息。
- **取消**：排队中任务立即终结；运行中任务逻辑取消并传播到执行引擎。
- **产物下载**：完成后可下载各节点产物文件（字幕、音频、JSON 结果等，
  归集自 `file_output` 与模块文件产物协议）。
- 运行中任务的状态经 WebSocket 实时推送，无需手动刷新。

## 7. 设置（`/settings`）

所有修改通过 `PUT /api/config` **深度合并、保存即落盘**到
`config/app.toml`；重启敏感项（监听地址/端口、解释器路径等）变更时
会提示需重启 daemon。各分区对应配置参考章节：

| 分区 | 对应配置 | 说明 |
|---|---|---|
| 服务器 | `[server]` | 监听地址/端口；开启公网访问前有显式安全警告 |
| 通用 | `[general]` | 语言、主题、日志级别、启动检查更新 |
| 计算 | `[compute]` | 设备分配策略、刷新间隔、显存超额分配、CUDA 库目录 |
| 端口 | `[ports]` | 模块端口分配范围 |
| 模型 | `[models]` | 缓存目录、HuggingFace 镜像、默认下载源、下载并发 |
| Python | `[python]` | 解释器/uv 路径、uv 缓存目录、constraints 文件 |
| 管线 | `[pipeline]` | 并行数、空闲看门狗超时、节点硬超时缺省、工作目录 |
| 网络与代理 | `[network]` | http/https/no_proxy，注入下载与模块子进程 |
| 整合包 | `[packs]` | 导入/构建暂存目录 |
| 高级 | — | 其余高级选项 |

完整字段参考见 [CONFIG_REFERENCE.md](CONFIG_REFERENCE.md)。

## 8. 典型使用流程详解

### 8.1 安装并跑通第一个模块（以 faster-whisper 为例）

1. **仪表盘**：确认依赖环境区 FFmpeg 就绪（video_to_srt 管线需要）。
2. **模块页**：找到 faster-whisper 卡片 → 点击启动。首次启动自动创建
   venv 并安装依赖（含 torch 时约 15–20 分钟），状态从「准备中」转为
   「运行中」。
3. **模型**：在 large-v3 / medium / small 变体中选择需要的 → 点击下载
   （可按需选 HuggingFace 或 ModelScope 源）。下载进度实时显示，
   完成后备注「已就绪」。
4. **直跑验证**（可选）：打开直跑抽屉，选 `transcribe` 能力，上传一段
   音频提交，确认返回识别文本。

### 8.2 跑一条管线并取回结果

1. **管线页**：加载自带管线 `video_to_srt`（视频 → 提取音频 → ASR → SRT）。
2. （可选）检查 VRAM 账本，确认显存预算无冲突。
3. 点击运行，在对话框中选择输入视频文件，提交。
4. **任务中心**：找到新任务，实时观察各节点状态；全部完成后在产物区
   下载 `.srt` 字幕文件。
5. 需要保留中间产物时，确认「设置 → 管线」的工作目录保留开关
   （`keep_workspace`）；产物位于 `workspace/<task-id>/` 下按节点分目录。

### 8.3 用整合包一键部署别人的工作流

1. **模块页** → 整合包导入（上传 `.epzip` / URL / 本地路径）。
2. 导入自动落位模块、模型、管线；缺失项（如本机未装的模块）体现在
   适配报告中，不会静默失败。
3. 按提示下载缺失模型、启动模块，随后在管线页即可看到新管线。
