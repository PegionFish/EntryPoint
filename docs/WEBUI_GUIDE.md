# WebUI 使用指引

> 适用于 EntryPoint v0.x | WebUI 为唯一 UI（桌面端已于 2026-08-13 退役）

本文档逐页介绍 EntryPoint WebUI 的功能与典型操作。WebUI 由 ep-daemon 托管，
浏览器访问 `http://127.0.0.1:9800`（以 `config/app.toml [server]` 配置为准）
即可使用，无需安装客户端。

---

## 1. 导航结构

| 路由 | 页面 | 定位 |
|---|---|---|
| `/` | 仪表盘 | 设备、模块、依赖环境的全局状态总览 |
| `/run` | 快速调用 | 单模块能力 ad hoc 直跑（任务化追踪，模型空闲自动下线） |
| `/pipeline` | 管线编辑器 | React Flow 画布编排 DAG 管线并在线执行 |
| `/triggers` | 触发器 | 目录监控自动触发：规则增删改查、直接/管线模式、触发历史 |
| `/tasks` | 任务中心 | 任务状态跟踪、取消、产物下载 |
| `/modules` | 模块与模型 | 模块生命周期、模型获取/切换、整合包管理（统一页） |
| `/settings` | 设置 | 全局配置（保存即落盘 `config/app.toml`） |

顶栏提供语言切换（简体中文 / English）与主题切换；界面文案走 i18n，
跟随「设置 → 通用」的语言配置。

## 2. 快速上手：一条典型流水线

```
① 仪表盘确认依赖环境就绪（FFmpeg；模块 venv 的 PyTorch CUDA 按需）
② 模块页：启动需要的模块（首次自动准备 venv 依赖）
③ 模块页：下载/上传/导入该模块的模型，必要时切换激活变体
④ 管线页：选一条自带管线（如 video_to_srt），运行并选择输入文件
⑤ 任务中心：跟踪节点进度，完成后下载产物（如 .srt 字幕）
```

下文按页展开。

## 3. 仪表盘（`/`）

三个区块：

- **设备**：枚举到的计算设备（GPU/CPU）与状态指标，是模块设备分配的依据。
- **模块**：全部已安装模块的运行状态一览（运行中/准备中/错误等），
  可快速定位需要启动或排障的模块。
- **依赖环境**：运行前置依赖的检测卡片——FFmpeg（版本与路径）、
  各模块 venv 内的 PyTorch CUDA 可用性；缺失项会给出安装指引文案。
  新装机器先看这里，缺失项不解决，相应管线节点会失败。

## 4. 模块与模型（`/modules`，统一页）

模块详情独立页已裁撤，本页集中承载模块、模型与整合包三类操作，
详情一律以**抽屉**形式展开。

### 4.1 模块卡片与抽屉

- 每个模块卡片显示名称、类别、运行状态徽章、激活模型变体与设备信息；
  提供启动 / 停止（带确认）/ 重启操作。
- **模块详情抽屉**：模块元信息、声明的能力（capabilities）列表与参数
  schema、激活变体切换器。
- **直跑抽屉**：不走管线、对单个能力做 ad hoc 调用——选能力、选输入文件、
  按参数 schema 自动生成的表单调参后提交，适合快速验证模块效果
  （全局「快速调用」页提供同等能力，见 §6）。
- **日志抽屉**：实时查看 daemon 捕获的该模块输出日志（搜索/过滤/导出）。
- 变体切换：单槽位语义——切换激活变体后按提示**重启模块**生效；
  目标变体本地缺失时提示一键下载。

### 4.2 模型获取

模型按「模块 → 变体」分组展示，支持 tag chips 筛选。每个模型卡片/行提供：

- **在线下载**：HuggingFace / ModelScope / URL 三类源 + 模块声明的
  `[[models.mirrors]]` 镜像源，下载时可选源；WebSocket 实时进度，可取消。
  首次下载会自动准备模块 venv（含大型依赖时约 15–20 分钟，属预期行为）。
- **浏览器上传**：整个文件夹多文件、zip、tar.gz 三种形态，服务端流式
  落盘并解包。
- **本地导入**：从服务器/本机已有目录导入。
- 其他：检查更新、删除（卡内操作）。

### 4.3 整合包（pack）

- **整合包抽屉**：已安装整合包列表与卸载（可选保留模型权重）。
- **导入**：本地路径 / URL / 浏览器上传三种入口；导入自动完成校验、
  落位（模块 + 模型 + 管线）与适配报告。
- **导出**：把现成模块构建成整合包下载（模块导出构建）。

格式与安全模型详见 [PACK_AUTHORING.md](PACK_AUTHORING.md)。

## 5. 管线编辑器（`/pipeline`）

基于 React Flow 的 DAG 画布：

- **节点库**（宽屏常驻左栏，窄屏为抽屉）：内置节点（file_input /
  file_output / ffmpeg / llm / file_archive / file_gate）+ 已安装模块声明的全部
  能力，数据驱动自动生成；拖拽或点击加入画布。
- **连线**：按端口类型校验（音频/视频/图片/文本/JSON/文件），类型不兼容
  的连线会被拒绝。
- **节点参数面板**：模块节点的参数表单由 module.toml 的 params schema
  自动渲染；还可设置节点超时、重试、变体 pin 与设备软约束。
- **管线管理**：加载自带/已保存管线（`config/pipelines/*.toml`，如
  `video_to_srt.toml`、`audio_extract.toml`）、保存（服务端持久化）、
  TOML 导入/导出（便于分发与版本管理）。
- **VRAM 账本**：按画布上的模块节点估算每设备显存占用，超预算会标红提示。
- **运行**：选输入文件后提交执行；画布上实时回显各节点状态
  （排队/运行中/完成/失败），完整跟踪见任务中心。

管线格式与执行语义详见 [PIPELINE_SPEC.md](PIPELINE_SPEC.md)。

## 6. 快速调用（`/run`）

与管线编辑器同级的单模块 ad hoc 直跑页：不用搭管线，选能力 → 给输入 →
调参 → 提交一气呵成。每次提交即创建一个正式任务，可在任务中心追踪、
取消、下载产物。模块页原有「直跑抽屉」保留不变（见 §4.1），与本页共用
同一套直跑链路。

- **能力目录**（左栏）：聚合全部已装模块声明的能力，顶部 category chips
  分类筛选（asr / tts / denoise / ocr / image 等）；每个条目显示模块名 +
  能力名 + 输入→输出类型，并以状态点区分运行中 / 已停止 / 模型未就绪。
- **两种输入形态**（按能力的 input_type 自动切换）：
  - 文件型（audio / video / image）：服务器路径直填或浏览器上传（大文件无忧）；
  - 文本型（text）：textarea 直接粘贴文本——TTS 类 text→audio 能力由此可用。
- **参数表单**：由 module.toml 的 params schema 自动渲染，含默认值与说明。
- **执行即受理**：点击执行秒级返回任务，不必等模块就绪——模块未运行时
  自动拉起（首次需准备 venv / 模型时耗时较长），冷启动全程以任务的节点
  状态可见可追踪，不阻塞提交。
- **页内会话任务区**：本次会话提交的任务以卡片列表展示——状态徽章、
  节点级进度（WebSocket 实时推送）、完成后产物预览与下载；卡片提供
  「在任务中心查看 →」深链，进入任务中心后自动展开并高亮该任务。
- **模型未就绪**：选中未就绪条目时给出「去模块页下载」引导，避免盲目提交。
- **空闲自动下线**：模块业务完成后持续空闲达到阈值即自动停止并释放算力
  （配置项 `[modules].idle_timeout_secs`，缺省 1800 秒 = 30 分钟，
  0 = 常驻，「设置 → 模块生命周期」可调）；venv 与模型权重保留，
  下次调用按需快速重载。页面底部有相应静态提示。

典型场景：单独给一个音频做 ASR：

1. 打开 `/run`，category 筛选 asr，选中 faster-whisper 的 `transcribe` 能力；
2. 上传目标音频（或直接填服务器路径），按需调整 language 等参数；
3. 点击执行——秒级受理后在页内任务卡看到排队 / 运行 / 完成，完成即可
   预览识别文本或下载 srt/txt 产物（也可经深链进入任务中心取件）。

## 7. 触发器（`/triggers`）

顶级导航「触发器」页：为监控目录配置**条件触发规则**——文件出现/更新并稳定后
自动执行处理。触发器是独立功能（独立规则、独立页面），简单需求（如「新视频
自动提取音频」）不必先造管线；复杂需求再走管线模式。触发语义详见
[AUTOMATION.md](AUTOMATION.md) §4。

### 7.1 规则列表

每条规则展示：名称、监控目录、动作模式（直接 / 管线）、启停开关、最近触发
速览（环形缓冲，最多 5 条）与关联任务深链。操作：

- **启停**：停用的规则完全不巡检；重新启用后首轮不触发存量文件。
- **编辑**：与新建同一对话框。
- **删除**：带确认；删除规则不影响已产生的任务与事件记录。

### 7.2 新建/编辑规则

**公共区：**

| 字段 | 说明 |
|---|---|
| 名称 | 非空；用于展示、事件记录与命名模板 `{rule}` 占位符 |
| 监控目录 | **绝对路径**（目录暂不存在仅告警不拒绝） |
| 递归子目录 | 默认关 |
| 扩展名过滤 | 白名单，空 = 全部（自动去点、转小写归一） |
| 稳定秒数 | 文件 mtime 需稳定该时长才触发（默认 30，最小 5）——防 BT/浏览器半截文件误触发 |
| 含存量文件 | 默认关（创建规则后仅处理新文件，不回灌）；开启后从现存最旧文件按 mtime 有序追赶 |
| 启用 | 建规则默认开启 |

半截文件后缀黑名单内建于引擎：`.part` `.tmp` `.download` `.!qB` `.crdownload`
`.bc` `.td` `.xltd` 后缀的文件永不触发。

**动作模式（必须恰好一个）：**

- **直接模式**（免管线）：
  - 「仅归档」：新文件按输出配置直接搬运归档；
  - 或选「模块 + capability」级联下拉（能力数据源与快速调用页相同）：文件自动
    送入该能力执行，产物按输出配置归档；模块未运行时自动拉起并等健康。
  - **输出配置**（直接模式必填）：目标目录（绝对路径）、命名模板
    （默认 `{name}.{ext}`，占位符 `{name}/{ext}/{date}/{datetime}/{rule}/{seq}`，
    详见 [PIPELINE_SPEC.md](PIPELINE_SPEC.md) §5.8）、冲突策略
    （追加序号 / 覆盖 / 跳过）。
- **管线模式**：选择已保存管线后**手动选择**该管线的 `file_input` 注入节点
  （从管线 spec 拉取候选）；触发时把命中文件的绝对路径注入该节点执行。

### 7.3 触发语义速览

daemon 每 **10 秒**轮询一次：仅 mtime 已稳定「稳定秒数」且晚于规则水位线
（checkpoint）的文件触发；每轮每规则至多 16 个、按 mtime 升序；全局在途任务
256 硬上限背压，队列满时文件保持待触发、下轮重试（不丢文件）。

### 7.4 触发历史

规则详情展示该规则的结构化触发记录（数据源为统一事件日志，最新在前）：
时间、文件、状态与关联任务。状态取值：

| 状态 | 含义 |
|---|---|
| `submitted` | 已提交执行（管线/直调任务已入队） |
| `rejected` | 提交被拒（如队列满）——文件保持待触发，下轮自动重试 |
| `archive_done` | 仅归档动作完成 |
| `archive_skipped` | 归档跳过（冲突策略为「跳过」且目标已存在） |

也可用 REST 查询：`GET /api/events?rule=<rule_id>`（见 §10 日志体系）。

## 8. 任务中心（`/tasks`）

- 任务列表：状态徽章（排队/运行中/完成/失败/已取消）、提交时间、
  所属管线，支持按状态筛选。
- 任务卡片展开后可见**节点级**进度与各节点耗时/错误信息。
- **取消**：排队中任务立即终结；运行中任务逻辑取消并传播到执行引擎。
- **产物下载**：完成后可下载各节点产物文件（字幕、音频、JSON 结果等，
  归集自 `file_output` 与模块文件产物协议）。
- 运行中任务的状态经 WebSocket 实时推送，无需手动刷新。

## 9. 设置（`/settings`）

所有修改通过 `PUT /api/config` **深度合并、保存即落盘**到
`config/app.toml`；重启敏感项（监听地址/端口、解释器路径等）变更时
会提示需重启 daemon。各分区对应配置参考章节：

| 分区 | 对应配置 | 说明 |
|---|---|---|
| 服务器 | `[server]` | 监听地址/端口；开启公网访问前有显式安全警告 |
| 通用 | `[general]` | 语言、主题、日志级别、启动检查更新、日志保留天数（§10） |
| 计算 | `[compute]` | 设备分配策略、刷新间隔、显存超额分配、CUDA 库目录 |
| 端口 | `[ports]` | 模块端口分配范围 |
| 模型 | `[models]` | 缓存目录、HuggingFace 镜像、默认下载源、下载并发 |
| Python | `[python]` | 解释器/uv 路径、uv 缓存目录、constraints 文件 |
| 管线 | `[pipeline]` | 并行数、空闲看门狗超时、节点硬超时缺省、工作目录 |
| 模块生命周期 | `[modules]` | 空闲自动下线超时（缺省 1800s，0 = 常驻） |
| 网络与代理 | `[network]` | http/https/no_proxy，注入下载与模块子进程 |
| 整合包 | `[packs]` | 导入/构建暂存目录 |
| 高级 | — | 其余高级选项 |

完整字段参考见 [CONFIG_REFERENCE.md](CONFIG_REFERENCE.md)。

## 10. 日志体系

EntryPoint 的日志分四类，位置、查看方式与保留策略各异：

| 日志 | 内容 | 位置 | 查看方式 | 保留策略 |
|---|---|---|---|---|
| daemon 运行日志 | daemon 自身 tracing 输出（级别 `RUST_LOG` 环境变量 > `[general].log_level`，支持运行期热调级） | **不落盘**：控制台 / systemd journal | 启动终端直接查看；systemd 部署用 `journalctl -u <service>` | 由宿主（journal）管理 |
| 模块进程日志 | daemon 捕获的各模块子进程 stdout/stderr 增量行 | `runtime/logs/<module>*.log` | 模块页「日志抽屉」（§4.1，实时/搜索/过滤/导出）；或直接读文件 | `[general].log_retention_days`（默认 90 天，`0` = 永久；按文件 mtime 巡检清理） |
| 任务注册表 | 任务生命周期记录（daemon 重启后非终态任务改判 failed） | `runtime/tasks/` | 任务中心页（§8）/ `GET /api/tasks` | 随任务保留，无自动清理 |
| 统一事件日志 | 结构化事件：`watcher_trigger`（触发器提交结果，§7.4）与 `task_terminal`（任务终态 completed/failed/cancelled + 错误摘要） | `runtime/logs/events-YYYY-MM.jsonl`（按月滚动，单行 JSON 追加） | 触发器页「触发历史」（§7.4）；REST `GET /api/events?rule=&type=&limit=`（默认 100，上限 1000）；或直接读文件（容忍尾行不完整/损坏） | `[general].log_retention_days` 同上 |

保留期清理由 daemon 每小时巡检一次：`log_retention_days > 0` 时删除
`runtime/logs/` 下 mtime 超期的 `events-*.jsonl` 与模块日志（`*.log`）；
`= 0` 表示永久保留（跳过清理）。保留天数在设置页「通用」分区修改，
保存即落盘（字段参考见 [CONFIG_REFERENCE.md](CONFIG_REFERENCE.md) §1.1）。

## 11. 典型使用流程详解

### 11.1 安装并跑通第一个模块（以 faster-whisper 为例）

1. **仪表盘**：确认依赖环境区 FFmpeg 就绪（video_to_srt 管线需要）。
2. **模块页**：找到 faster-whisper 卡片 → 点击启动。首次启动自动创建
   venv 并安装依赖（含 torch 时约 15–20 分钟），状态从「准备中」转为
   「运行中」。
3. **模型**：在 large-v3 / medium / small 变体中选择需要的 → 点击下载
   （可按需选 HuggingFace 或 ModelScope 源）。下载进度实时显示，
   完成后备注「已就绪」。
4. **直跑验证**（可选）：打开直跑抽屉，选 `transcribe` 能力，上传一段
   音频提交，确认返回识别文本。

### 11.2 跑一条管线并取回结果

1. **管线页**：加载自带管线 `video_to_srt`（视频 → 提取音频 → ASR → SRT）。
2. （可选）检查 VRAM 账本，确认显存预算无冲突。
3. 点击运行，在对话框中选择输入视频文件，提交。
4. **任务中心**：找到新任务，实时观察各节点状态；全部完成后在产物区
   下载 `.srt` 字幕文件。
5. 需要保留中间产物时，确认「设置 → 管线」的工作目录保留开关
   （`keep_workspace`）；产物位于 `workspace/<task-id>/` 下按节点分目录。

### 11.3 用整合包一键部署别人的工作流

1. **模块页** → 整合包导入（上传 `.zip`/`.tar.gz` 归档 / URL / 本地路径）。
2. 导入自动落位模块、模型、管线；缺失项（如本机未装的模块）体现在
   适配报告中，不会静默失败。
3. 按提示下载缺失模型、启动模块，随后在管线页即可看到新管线。

### 11.4 用快速调用做单步处理

只想对单个文件做一步处理（转写、降噪、抠图等）时，无需搭建管线：

1. 打开 `/run`，在能力目录按类别筛选并选中目标能力
   （如 faster-whisper 的 `transcribe`）；
2. 给输入（文件路径直填 / 浏览器上传，文本型能力则直接粘贴文本），
   按 params schema 表单调参；
3. 点击执行即受理为任务——页内卡片实时看进度、取产物，
   或从「在任务中心查看」深链进入任务中心跟踪。

需要多步串联（如视频 → 提取音频 → ASR → 字幕）时再回到管线页（见 §11.2）。
